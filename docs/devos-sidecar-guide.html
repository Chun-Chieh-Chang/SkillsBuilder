SkillsBuilder Sidecar 架構

核心分離、極致 Token 節省、動態按需掛載

1. 核心理念 (The Sidecar Concept)

SkillsBuilder DevOS 採用「邊車架構 (Sidecar Architecture)」，將複雜的技能庫 (Skills) 與開發規則與您的專案源碼完全分離。

不再需要：將數百個 SKILL.md 檔案拷貝進您的新專案中。

改為：在專案中建立一個輕量級的「導向指標 (Pointer)」，引導 AI Agent 訪問全域安裝的技能中心。

2. 優勢 (Benefits)

極致 Token 節省

Agent 不再需要掃描專案內數百個技能檔案，大幅減少 Context 佔用，開發成本降低 80% 以上。

保持專案純淨

專案目錄僅保留您的程式碼與一個 GEMINI.md，完全符合 MECE 原則。

全域同步更新

只要更新一次全域技能池，所有掛載 Sidecar 的專案將立即獲得最新的開發能力。

一鍵無縫整合

使用標準 Bootstrap 指令即可在 3 秒內完成新專案的智能化武裝。

3. 如何初始化 (How to Initialize)

在任何新專案的根目錄下，執行以下 PowerShell 指令：

powershell -ExecutionPolicy Bypass -Command "iex ((New-Object Net.WebClient).DownloadString('https://raw.githubusercontent.com/Chun-Chieh-Chang/SkillsBuilder/main/bootstrap.ps1'))"

腳本行為：

  • 1
    自動偵測環境，若非 SkillsBuilder 核心庫，則啟動 Sidecar 模式。
  • 2
    在 GEMINI.md 中注入全域路徑指標 (Global Pointer)。
  • 3
    配置必要的 IDE 規則，讓 Agent 具備「1% Rule」意識。

4. 協作方式 (How to Collaborate)

當您與 IDE Agent (如 Gemini CLI, Claude Code) 協作時，Agent 會讀取到 GEMINI.md 中的指令：

# 🚀 SkillsBuilder DevOS Sidecar Context
All professional development skills are globally installed at:
C:/Users/User/.gemini/antigravity/skills

Agent 行為邏輯：

  1. 當收到任務時，Agent 會優先檢索全域路徑。
  2. 若發現相關技能（如 python-reviewer），則動態讀取該檔案並執行。
  3. 1% Rule：Agent 必須時刻思考是否有現成技能可用。

5. 自我進化與檢索 (Auto-Evolution)

如果本地與全域都沒有適合的技能怎麼辦？

SkillsBuilder 的 github-skill-search 功能會被觸發，Agent 會自主到 GitHub 尋找最新的開發工具、MCP Server 或技能範本，並自動將其整合進全域技能池中。

這意味著您的開發助理會隨著技術迭代而不斷變強。
